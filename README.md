# School-Budget

ระบบงบประมาณของโรงเรียนค่ายบางระจันวิทยาคม แยกจาก School-Portal และ School-Procurement

## หน้าที่ใช้งาน

- `index.html` เปิดภาพรวมงบประมาณ
- `budget-dashboard.html` / `.css` / `.js` ภาพรวมและการ์ดรายรับ–คงเหลือ
- `budget-projects.html` / `.css` / `.js` โครงการและกิจกรรม
- `budget-balances.js` สรุปรายรับและยอดคงเหลือจาก Sheet ยอดคงเหลือ
- `budget-project-ledgers.js` รายการทะเบียนใช้เงินรายโครงการ
- `budget-data.json` สำเนาข้อมูลหลักจากทะเบียนคุมเงินบริหารวิชาการ 2569 ยังไม่ซิงก์อัตโนมัติ
- `budget-sidebar.js` / `.css` Sidebar กลางที่ระบบเอกสารเรียกใช้ร่วมกัน
- `legacy-dashboard.html` หน้าทดลองเดิมที่เก็บไว้ก่อนย้ายระบบ ไม่ใช่หน้าหลัก

## การยืมงบประมาณ

- ผู้ดูแลกด **เพิ่มการยืมเงิน** ในโครงการปลายทางแล้วจึงเปิดฟอร์ม เลือกฝ่าย/โครงการ/ทะเบียนต้นทางและดูยอดทั้งสองฝั่งก่อนบันทึก
- รองรับปีเดียวกันและประเภทงบเดียวกัน รวมถึงกิจกรรมที่มีทะเบียนแยกในโครงการเดียวกัน; ไม่เดายอดกิจกรรมที่ยังไม่มีทะเบียนแยก
- `apps-script/Borrowing.gs` บันทึกรายการกลางหนึ่งแถวในแท็บ `ทะเบียนยืมงบประมาณ` ของสำเนาวิชาการตามปี ทุกฝั่งคำนวณจากรายการกลางเดียวกัน แยกจากรายจ่าย
- ไม่เขียนรายการยืมเป็นค่าใช้จ่ายในคอลัมน์ E/H ของทะเบียนเดิม และไม่แก้งบตั้งต้น: ยอดหน้าเว็บ = คงเหลือทะเบียนค่าใช้จ่าย + รับยืม − ให้ยืม ดังนั้นคอลัมน์ F ในชีทเดิมเป็นยอดก่อนรวมทะเบียนการยืม
- บันทึกภายใต้ล็อก ตรวจยอดและ revision ทั้งสองฝั่ง ใช้ request ID ป้องกันซ้ำ และตรวจสิทธิ์ admin ที่เซิร์ฟเวอร์
- ยกเลิกด้วยรายการย้อนกลับที่อ้างอิงรหัสเดิม ไม่ลบประวัติ และไม่ให้คืนยอดจนปลายทางติดลบเพิ่มจากก่อนยืม
- `budget-borrowing.js` แสดงฟอร์ม/ประวัติพร้อมลิงก์ต้นทางปลายทาง ส่วน `budget-live-data.js` รวมผลการยืมล่าสุดเข้าข้อมูลนำเข้าของหน้าภาพรวม/โครงการ โดยไม่เพิ่มยอดรายรับรวมโรงเรียน
- การใช้จ่ายและการแก้ข้อมูลใน Excel ยังไม่มีการซิงก์ยอดฐานของภาพรวมอัตโนมัติ รายการยืมอ่านจากระบบจริงทุกครั้งที่เปิดหน้า
- โครงการที่มีประวัติการยืมอ่านคงเหลือทะเบียนล่าสุดจากสำเนาด้วย เพื่อให้ค่าใช้จ่ายหลังยืมลดยอดบนหน้าภาพรวมและโครงการตามกัน; โครงการที่ยังไม่มีรายการยืมยังใช้ข้อมูลฐานนำเข้า

สถานะเผยแพร่: เวอร์ชัน 8 เปิดการยืม ยกเลิก และส่งยอดคงเหลือทะเบียนล่าสุดของโครงการที่มีประวัติยืมใน `getBudgetAdjustmentSummary` แล้ว ใช้เฉพาะไฟล์สำเนาที่กำหนดไว้ ดู `apps-script/deployment-status.json`


## เอกสารงบ 1 และ งบ 2

เมนูใหม่ใช้ `budget-documents.html` เป็นหน้าประวัติ และ `budget-document-editor.html` เป็นหน้าจัดทำ แยกตัวจัดเก็บใน `budget-document-store.js` (`school-budget-forms-history-v1` และฉบับร่างแยกตาม ID) ออกจากเอกสารจัดซื้อจัดจ้างโดยสิ้นเชิง ประวัติปัจจุบันเก็บใน localStorage ของเบราว์เซอร์ ไม่ใช่ Cloud

ตัวพารามิเตอร์และแบบ A4 อยู่ใน `budget-document-templates.js` อ้างอิง Word งบ 1 / งบ 2 ที่ผู้ใช้ให้ มีตัวครุฑและฟอนต์แยกของส่วนนี้ ตารางแนบมีเส้นตามแบบและสร้างหน้าต่อพร้อมหัวตารางซ้ำเมื่อเต็ม เลือกพิมพ์ งบ 1 พร้อมแนบ / งบ 2 / ทั้งชุด และ Save as PDF ผ่าน browser print

`budget-document-editor.js` เรียกเฉพาะ `getBudgetRegister` อ่านทะเบียนสำเนา เลือกปี ฝ่าย โครงการ กิจกรรม และประเภทงบ รวมยอด used และ current ของทุก block ภายในประเภทงบเดียวกัน ยอด current รวมผลยืมจาก backend เดิมแล้ว ไม่ใช้ received-current เป็นรายจ่ายเพราะอาจมีเงินยืม ไม่ใช้ snapshot นำเข้าเป็นยอดปัจจุบัน ยอดไม่ทราบหรือชื่อประเภทงบไม่ตรงจะไม่ให้พิมพ์ เมื่อยอดที่อ่านเกิน 2 นาทีจะให้อ่านใหม่และตรวจยอดก่อนกดพิมพ์อีกครั้ง การพิมพ์และบันทึกเอกสารไม่เรียก API เขียนทะเบียน

รักษาสิทธิ์เดิม: admin ทั้งสองบัญชีทำส่วนงบประมาณได้ editor ใช้ได้เฉพาะเอกสารจัดซื้อจัดจ้าง จึงไม่เปิดการแก้ไขเอกสารงบใหม่ให้ editor หรือ Guest ทดสอบด้วย `node tests/budget-documents.cjs` (ใช้ runtime Playwright เช่นเดียวกับการทดสอบอื่น) ครอบคลุมยอดปัจจุบัน ยืมที่รวมใน current พิมพ์แยก บันทึกแยก เปิดกลับ รายการยาว หน้าต่อ มือถือ และสิทธิ์


### กลุ่มช่องกรอกและแท็บ งบ 1 / งบ 2

`budget-document-sections.js` จัดย้ายช่องกรอกเดิมเป็นกลุ่ม details/summary โดยไม่คัดลอกข้อมูลหรือสร้าง event listener ของการเงินซ้ำ แท็บ งบ 1 / งบ 2 แสดงหัวกระดาษและข้อมูลตรงกลางของเอกสารที่เลือก พร้อมพรีวิวที่ตรงกัน โครงการและยอดเงินอยู่ในข้อมูลใช้ร่วมกัน ผู้ลงนามและความเห็นแยกกรอบย่อไว้ก่อน สถานะย่อ/ขยายและแท็บล่าสุดเก็บเฉพาะ sessionStorage การพิมพ์ทั้งชุดยังรวมทุกหน้าและคืนแท็บเดิมเมื่อปิดหน้าต่างพิมพ์

Guest ใช้เมนูเอกสารงบ 1–2 ได้: ดูประวัติ/รายละเอียด และสร้างเอกสารใหม่ เมื่อบันทึกแล้วอ่านอย่างเดียว ไม่แก้เอกสารเดิม ประวัติยังเก็บเฉพาะเบราว์เซอร์นี้ ไม่มีการซิงก์ข้ามเครื่อง ตัวอ่าน `getBudgetDocumentFinance` คืนเฉพาะประเภทงบและยอดรวม ไม่คืนรายการทะเบียน หมายเหตุ หรือ URL ชีท การบันทึกเอกสารไม่ลงรายจ่ายทะเบียน

ทะเบียนโครงการที่ 4 มีหัว G เป็นหมายเหตุ แต่เซลล์จริงเป็นสูตรยอดใช้สะสม ระบบแยกตามหัวตาราง/สูตรและผลรวม ไม่เอาค่า H ที่ไม่มีหัวข้อมาเดาเป็นหมายเหตุ ข้อมูลเดิมไม่ถูกแก้ เมื่อบันทึกแถวใหม่ หมายเหตุจะใช้คอลัมน์หมายเหตุที่มีอยู่หรือคอลัมน์ว่างแยกที่ตรวจแล้ว โดยไม่เขียนทับตัวเลขเก่า

ประวัติเอกสารงบ 1–2: admin เลือกลบทีละรายการหรือเลือกทั้งหมดที่แสดงตามตัวกรอง พร้อมกรอบยืนยันและคืนค่าชุดที่ลบล่าสุดได้หลังโหลดหน้าใหม่ Guest ไม่มีสิทธิ์ลบ/คืนค่า ทั้งหมดเป็นประวัติในเบราว์เซอร์ ไม่เรียกแก้ทะเบียนในชีท

## เอกสารเบิกจ่ายค่าจ้างรายเดือน
- `disbursement.html` ประวัติ และ `disbursement-editor.html` แบบกรอกครบทั้งชุดต่อผู้รับจ้างหนึ่งคนต่อเดือน
- แยกไฟล์ `disbursement-editor.js`, `disbursement-templates.js`, `disbursement-history.js`, `disbursement-store.js`, `disbursement.css` จากระบบเดิม
- ใช้ได้เฉพาะ role admin/editor ทุกบัญชี Guest ไม่เห็นเมนูและต้องเข้าสู่ระบบเมื่อเข้าตรง
- Checklist, หนังสือนำส่ง, ใบส่งมอบงาน, ใบตรวจรับ และบันทึกรายงานผลตรวจรับ อ้างอิง Word ที่ผู้ใช้ให้ ข้อมูลร่วมใช้ครั้งเดียวทั้งชุด
- ค่าจ้าง หักวันไม่ปฏิบัติงาน (อัตราแก้ได้) ภาษีที่กรอกเอง และยอดสุทธิคำนวณหน่วยสตางค์ ไม่เดาอัตราภาษี ไม่ลงทะเบียนงบประมาณ
- ฉบับร่างแยกตามบัญชี/เลขเอกสาร ประวัติแยกที่ `school-monthly-disbursement-history-v1` ในเบราว์เซอร์เท่านั้น
- บันทึกร่างได้ ต้องกรอกครบทั้งชุดก่อนเลือกพิมพ์ทั้งชุดหรือบางใบผ่านหน้าต่างพิมพ์/PDF
- บันทึกปฏิบัติงานประจำวันและสำเนาสัญญาเป็นเอกสารแนบภายนอก ไม่สร้างอัตโนมัติ
